# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。
- 每笔收款与冲正都必须留痕，记录含业务流水标识、操作类型、金额、发生时间与发起方标识；同一订单的流水按发生顺序返回。
- 冲正只能作用于属于当前租户、且属于该订单的收款记录；冲正金额等于原收款金额，不支持部分冲正；同一笔收款只能冲正一次。
- 冲正为原子操作：冲正成功后订单的已收/未收金额与状态必须与从未发生该笔收款一致（已结清的订单冲正后回到未结清）；冲正记录通过原流水标识与原收款关联，可据此重建因果链。
- 订单不存在、流水不存在、跨租户、重复冲正、冲正后金额不合法等失败必须可区分，且任一失败都不得改动账面与流水；同一冲正请求重放只生效一次。
- 分期计划以（租户, 订单标识, 期次标识）唯一；同一订单的计划只能受理一次，重复受理必须被拒绝且不改动已受理计划。
- 分期计划整份校验、整份落库：各期应收之和必须等于订单金额，期次标识不得重复，金额必须为正；任一不合法则整份拒绝且不留任何一期。
- 受理分期计划后，登记收款必须声明期次标识，收款金额必须等于该期应收；收款成功后该期标记为已收，订单已收/未收与状态按原有规则推进，全部期次收讫时订单结清。
- 未声明期次、金额与该期应收不等、期次不存在、期次已收讫、未受理计划却按期次收款，必须是可区分的拒绝原因，且不改动账面与任何留痕；同一期次并发收款至多一笔成功，同一收款请求重放只生效一次。
- 对分期收款的冲正必须连同期次一起退回未收：冲正成功后该期回到未收状态，订单已收、未收与状态与该笔收款从未发生完全一致；期次状态、账面与流水留痕在同一事务内原子提交。
- 分期计划与每期收讫状态必须可查询；跨租户查询一律按不存在处理，不泄漏对象是否存在。
- 已收款订单可按业务需要退款。登记退款给定订单标识、原收款流水标识与退款金额；退款成功后订单已收金额按净收款（收款−冲正−退款）减少，未收金额按“订单金额−收款与退款相抵后的净额”重算：未收转为正数的订单不再视为结清，净收款全部退完的订单回到未收款状态。
- 退款金额必须为正，且不得超过可退余额（订单当前净收款，且不超过该笔原收款金额减去已挂在其名下的退款）；超出可退余额必须拒绝且账面与留痕不变。支持对同一笔收款分多次部分退款。
- 对分期收款登记的退款必须声明对应期次标识，且只能退该期当前已收的金额；退款成功后该期回到未收状态并清空关联的收讫流水引用，可再次收讫。分期退款未声明期次、期次不存在、该期未收讫、退款金额与该期已收金额不符，必须是可区分的拒绝原因。整单收款的退款无需也不得声明期次。
- 退款只能作用于属于当前租户且属于该订单的收款；跨租户一律按订单不存在处理，不泄漏对象是否存在。
- 每笔退款必须在收款流水中写入一条退款记录，含业务流水标识、金额、发生时间与发起方标识，并通过被退款的收款流水标识关联原收款；流水查询按发生顺序将收款、冲正、退款一并返回，据此可重建一笔款项从收讫到退回的完整因果链。
- 退款为原子操作：订单不存在、金额非正、超出可退余额、期次缺失或期次未收讫等失败必须可区分，且任一失败都不改动已收、未收、状态、期次状态与流水；同一退款请求重放只生效一次，重复退款同一笔收款不重复扣减也不重复留痕；中断续跑后账面、期次状态与流水始终闭合。
- 批量收款导入按业务文件一次性受理一批外部收款登记：请求给定导入文件路径（CSV，表头为 order_id,amount_cents[,installment_id]）与发起方标识；发起方标识记入每笔成功收款的流水留痕，未声明时沿用单笔收款的缺省规则（取租户标识）。
- 导入按文件中行的先后顺序逐行受理，每行的业务校验与账面推进完全等同于对该订单单独登记一笔收款：收款不得超过未收金额；已受理分期计划的订单必须声明期次且金额等于该期应收；期次不存在、期次已收讫、未受理计划却按期次收款等拒绝原因与单笔收款完全一致。
- 任一行不合法只拒绝该行，不影响同批其他行生效，也不允许一行的部分效果残留：每行的收款留痕、账面/期次推进与逐行结论在同一事务内原子提交。每行对应一条明确结论：成功行给出受理后的已收、未收与状态及收款流水标识；失败行给出与单笔收款一致的可区分拒绝原因；文件内无法解析的行给出稳定的行级格式错误原因。
- 每次导入生成一个可查询的导入批次标识，凭该标识可随时查询本次导入的逐行结论；跨租户查询一律按批次不存在处理，不泄漏对象是否存在。
- 同一文件路径与发起方标识重复提交视为同一批次：返回首次导入的结论，不重复记账、不重复留痕；不同发起方为不同批次，仍受账面规则约束（重复收款按超限等原因拒绝）。
- 同一订单标识在同一文件中出现多行时逐行按顺序受理，各行结论按发生先后如实反映前序行已推进的账面。
- 批量导入必须可续跑：导入中途服务重启，未完成的批次凭批次标识可查询到已完成行的结论（未完成行呈现为待受理）；续跑同一文件只补齐剩余行，已生效的行不重复记账、不重复留痕，全部行完成后批次收尾。
- 跨租户的订单在导入中一律按订单不存在处理，不泄漏对象是否存在，且不改动对象属主视角下的账面与流水。
- 批量导入成功行写入的收款流水与单笔收款完全同构，可被正常冲正与退款；冲正、退款后期次与账面规则不变。
