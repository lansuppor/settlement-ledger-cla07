# 经营单据与结算服务

本地可运行的多租户经营单据服务。当前支持受理订单、按标识读取订单、登记收款并核对未收金额、登记收款冲正，以及按订单查询收款流水（含按业务发生时间的范围查询）；数据落本地 SQLite 文件库，服务为单进程 HTTP 服务。

## 环境与安装

- Python 3.11
- `python3 -m venv .venv && . .venv/bin/activate && pip install -e .`

## 启动

- `python3 -m app.entry --port 8000`
- 健康检查：`GET /health`

## 测试

- `pytest -q`
- 静态检查：`ruff check .`

## 已有公开接口

- `POST /orders`：受理订单。请求字段 `tenant`、`order_id`、`amount_cents`、`currency`。成功返回 201 与订单对象；参数不合法返回 400；同一租户重复受理返回 409。
- `GET /orders/{order_id}`：按标识读取订单。租户通过请求头 `X-Tenant` 传入；不存在返回 404；跨租户读取返回 404（不泄漏对象是否存在）。
- `POST /orders/{order_id}/payments`：登记收款。请求字段 `amount_cents`；可选字段 `occurred_at`（本次收款的业务发生时间，取值规则见下文）；超过未收金额返回 409；成功返回 200 与订单的 `paid_cents`、`outstanding_cents`。
- `POST /orders/{order_id}/reversals`：登记一次收款冲正。租户通过请求头 `X-Tenant` 传入；请求字段 `reversal_id`（冲正标识，最小长度 1）与 `amount_cents`（本次冲正金额，最小货币单位整数，必须大于 0）；可选字段 `occurred_at`（本次冲正的业务发生时间，取值规则见下文）。
  - 成功返回 200 与订单对象（含冲正后的 `paid_cents`、`outstanding_cents` 与按新口径回算的 `status`）；同一 `reversal_id` 重发且订单标识与金额一致时，幂等返回 200，账务只扣减一次。
  - 冲正金额超过当前已收金额、或同一 `reversal_id` 的业务内容与首次不一致，返回 409 且不改变任何账务。
  - 订单不存在或属于其他租户返回 404（不泄漏对象是否存在）；缺少租户请求头返回 400。
- `GET /orders/{order_id}/flow`：按订单标识读取该订单的收款流水清单。租户通过请求头 `X-Tenant` 传入。
  - 成功返回 200，载荷为 `{"order_id": ..., "entries": [...]}`，`entries` 按生效先后（`seq` 从 1 递增）排列；每次成功生效的收款登记与冲正都出现且只出现一次。
  - 每条流水含：`seq`（该订单内的生效序号）、`entry_id`（订单内唯一、可区分同类型多次操作的流水标识，如 `pay-1`、`rev-2`）、`entry_type`（`payment` 收款 / `reversal` 冲正）、`amount_cents`（本次金额，最小货币单位整数）、`paid_cents` / `outstanding_cents` / `status`（本次操作生效后的已收、未收与订单状态快照）、`occurred_at`（本次业务的业务发生时间，带时区偏移的完整日期时间，精确到秒，如 `2026-10-02T15:04:05+08:00`）；冲正条目另含 `reversal_id`，可从流水定位回当初那次冲正，收款条目该字段为 `null`。
  - 订单尚无收款/冲正时，`entries` 为空数组（订单本身存在）。
  - 重复提交的冲正（幂等返回）与被拒绝（409/404/400/422）的收款、冲正不产生新流水，也不改变已有流水的内容与顺序。
  - 订单不存在或属于其他租户时返回 404（不泄漏对象是否存在）；缺少租户请求头返回 400。查询只返回本租户名下订单的流水。
- `GET /orders/{order_id}/flow/range`：按订单标识查询该订单在给定时间范围内生效的收款与冲正。租户通过请求头 `X-Tenant` 传入；查询参数 `start` 与 `end` 为区间起点与终点（均为必填，格式为带时区偏移的完整日期时间，精确到秒）。
  - 范围以业务发生时间 `occurred_at` 为准，返回区间内（含起点与终点）生效的全部流水；早于起点或晚于终点的流水不出现在结果中。不同时区偏移按同一时刻比较（如 `2026-02-10T09:00:00+08:00` 与 `2026-02-10T01:00:00+00:00` 为同一时刻）。
  - 成功返回 200，载荷为 `{"order_id": ..., "entries": [...]}`；`entries` 按生效先后（`seq` 升序）排列，与收款流水清单的顺序口径一致，各条流水的内容与清单返回完全一致；区间内没有流水时 `entries` 为空数组（订单本身存在）。
  - 缺少起点或终点、起点或终点不是合法的完整日期时间、或起点晚于终点时，返回 400（参数错误，可与 404 区分），且不读取任何数据。
  - 订单不存在或属于其他租户时返回 404（不泄漏对象是否存在）；缺少租户请求头返回 400。
- `GET /health`：返回服务与数据库状态。

## 业务发生时间的取值规则

- 每一次成功生效的收款登记或收款冲正都记录一个业务发生时间 `occurred_at`，最小精确到秒，随流水持久化，服务重启后保持不变。
- 调用方可在登记收款 / 收款冲正的请求体中通过可选字段 `occurred_at` 自行提供本次业务发生时间；提供且合法时按该时间记账。合法格式为带时区偏移的完整日期时间（精确到秒），如 `2026-10-02T15:04:05+08:00`；格式不合法（缺日期、缺秒、缺时区偏移、无法解析）时请求返回 400，且不改变任何账务、不产生流水。
- 未提供 `occurred_at` 时，由服务按当前时间（服务所在时区、带偏移）记账。
- 流水清单与范围查询中的 `occurred_at` 均以带时区偏移的完整日期时间（到秒）返回。

## 数据与配置

- 数据库文件默认 `var/app.sqlite`（不入库）。
- 环境变量：`APP_DB`（数据库路径）、`APP_PORT`（监听端口）、`APP_TENANT_HEADER`（默认 `X-Tenant`）。

## 当前限制

- 单进程运行，单库写入，未做连接池与写并发调优。
- 租户通过请求头声明，未接入真实身份提供方。
- 无缓存层；批量导入只支持小样本同步方式。
- 收款只支持整单登记，未实现分期、退款（冲正仅冲减已登记收款，不涉及原路退款）；对账能力目前提供按订单的收款流水查询与按业务发生时间的范围查询。
- 流水持久化于同一 SQLite 文件，服务重启后顺序、金额、账务快照与业务发生时间保持不变，新操作继续在末尾追加；单库单进程下依赖事务保证追加顺序，未做多副本一致性。
