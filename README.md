# 经营单据与结算服务

本地可运行的多租户经营单据服务。当前支持受理订单、按标识读取订单、登记收款并核对未收金额、登记收款冲正、按订单查询收款流水，以及按业务发生时间范围查询某段时期生效的收款与冲正，并提供按对账时区偏移分组的按日收款汇总；每笔收款与冲正都记录业务发生时间（最小精确到秒、带时区偏移），读回时保留登记时的偏移写法。数据落本地 SQLite 文件库，服务为单进程 HTTP 服务。

## 环境与安装

- Python 3.11
- `python3 -m venv .venv && . .venv/bin/activate && pip install -e .`

## 启动

- `python3 -m app.entry --port 8000`
- 健康检查：`GET /health`

## 测试

- `pytest -q`
- 静态检查：`ruff check .`

## 已有公开接口

- `POST /orders`：受理订单。请求字段 `tenant`、`order_id`、`amount_cents`、`currency`。成功返回 201 与订单对象；参数不合法返回 400；同一租户重复受理返回 409。
- `GET /orders/{order_id}`：按标识读取订单。租户通过请求头 `X-Tenant` 传入；不存在返回 404；跨租户读取返回 404（不泄漏对象是否存在）。
- `POST /orders/{order_id}/payments`：登记收款。请求字段 `amount_cents`，可选字段 `business_time`（本次收款的业务发生时间）。超过未收金额返回 409；成功返回 200 与订单的 `paid_cents`、`outstanding_cents`。
- `POST /orders/{order_id}/reversals`：登记一次收款冲正。租户通过请求头 `X-Tenant` 传入；请求字段 `reversal_id`（冲正标识，最小长度 1）、`amount_cents`（本次冲正金额，最小货币单位整数，必须大于 0），可选字段 `business_time`（本次冲正的业务发生时间，取值规则与登记收款一致）。
  - 成功返回 200 与订单对象（含冲正后的 `paid_cents`、`outstanding_cents` 与按新口径回算的 `status`）；同一 `reversal_id` 重发且订单标识与金额一致时，幂等返回 200，账务只扣减一次。
  - 冲正金额超过当前已收金额、或同一 `reversal_id` 的业务内容与首次不一致，返回 409 且不改变任何账务。
  - 订单不存在或属于其他租户返回 404（不泄漏对象是否存在）；缺少租户请求头返回 400。
- **业务发生时间取值规则**（收款与冲正共用）：`business_time` 必须是带时区偏移的完整日期时间、最小精确到秒，形如 `2026-10-02T08:30:00+08:00` 或 `2026-10-02T00:30:00Z`；不接受只到日期/分钟、不带时区偏移、小数秒或历法不存在的值。提供合法值时按该时间记账；未提供（缺省或为 `null`）时由服务按当前时间记账。非法值返回 400，且不改变任何账务、不产生流水。服务统一换算为 UTC 时刻存储，同一时刻的不同时区写法等价，不因写法不同重复记账或漏记；**读回时保留登记时的偏移写法**（登记为 `+08:00` 即按 `+08:00` 返回，`Z` 按 `+00:00` 返回），服务自行记账的记录以服务当前时间的偏移写法返回。
- `GET /orders/{order_id}/flow`：按订单标识读取该订单的收款流水清单。租户通过请求头 `X-Tenant` 传入。
  - 成功返回 200，载荷为 `{"order_id": ..., "entries": [...]}`，`entries` 按生效先后（`seq` 从 1 递增）排列；每次成功生效的收款登记与冲正都出现且只出现一次。
  - 每条流水含：`seq`（该订单内的生效序号）、`entry_id`（订单内唯一、可区分同类型多次操作的流水标识，如 `pay-1`、`rev-2`）、`entry_type`（`payment` 收款 / `reversal` 冲正）、`amount_cents`（本次金额，最小货币单位整数）、`paid_cents` / `outstanding_cents` / `status`（本次操作生效后的已收、未收与订单状态快照）、`business_time`（该条的业务发生时间，带时区偏移的完整日期时间、到秒，**按登记时的偏移写法返回**，如登记 `2026-10-02T08:30:00+08:00` 即返回同一写法，服务自行记账的记录以服务当前时间的偏移返回）；冲正条目另含 `reversal_id`，可从流水定位回当初那次冲正，收款条目该字段为 `null`。
  - 订单尚无收款/冲正时，`entries` 为空数组（订单本身存在）。
  - 重复提交的冲正（幂等返回）与被拒绝（409/404/400/422）的收款、冲正不产生新流水，也不改变已有流水的内容与顺序。
  - 订单不存在或属于其他租户时返回 404（不泄漏对象是否存在）；缺少租户请求头返回 400。查询只返回本租户名下订单的流水。
- `GET /orders/{order_id}/flow/range`：按订单标识查询该订单在给定时间范围内生效的收款与冲正。租户通过请求头 `X-Tenant` 传入；区间以查询参数 `start`、`end` 给出，二者都必填，取值规则与业务发生时间一致（带时区偏移的完整日期时间、到秒）。
  - 成功返回 200，载荷结构、`entries` 中各条字段及内容与 `GET /orders/{order_id}/flow` **完全一致**；返回业务发生时间落在闭区间 `[start, end]` 内的全部流水（起点、终点恰为边界值时包含对应流水），早于起点或晚于终点的流水不混入；结果按生效先后（`seq` 升序）排列，与流水清单的顺序口径一致。不同时区写法先换算到同一时刻再比较。
  - 空结果：区间合法但无流水落入（或订单尚无任何收款/冲正）时返回 200 与空数组。
  - 参数无效：缺少 `start`/`end`、`start` 或 `end` 不是合法完整日期时间、起点晚于终点，均返回 400 且错误信息可区分（`start is required` / `end is required` / `start must be...` / `end must be...` / `start must not be later than end`）；参数校验先于数据读取，参数非法时不读取任何订单或流水数据。缺少租户请求头返回 400。
  - 订单不存在或属于其他租户时返回 404（不泄漏对象是否存在）。查询只返回本租户名下订单的流水。
- `GET /orders/{order_id}/flow/daily-summary`：按订单标识查询该订单在给定时间范围内、按对账时区偏移归组的收款与冲正按日汇总。租户通过请求头 `X-Tenant` 传入；查询参数 `start`、`end` 二者都必填，取值规则与区间查询一致（带时区偏移的完整日期时间、到秒）；另需必填 `offset`（对账时区偏移，形如 `+08:00`、`-05:00` 或 `Z`）。
  - 分组规则：先以业务发生时间的 UTC 基准时刻做闭区间 `[start, end]` 取数（边界值恰在起点或终点时计入，早于起点或晚于终点不计入任何分组），再把每条流水换算到 `offset` 后的日历日归组；区间内每条流水恰计入一个日分组，跨日、跨时区分组不重复、不漏计。无流水的日期不出现，结果按日期升序。
  - 成功返回 200，载荷为 `{"order_id": ..., "offset": ..., "groups": [...]}`；每组含：`date`（该对账偏移下的日历日，如 `2026-05-20`）、`payment_cents`（该日收款合计）、`reversal_cents`（该日冲正合计）、`entry_count`（该日流水条数）、`first_business_time` / `last_business_time`（组内最早/最晚业务发生时间，按对账偏移写法返回、到秒）。各组条数之和等于区间内流水条数，收款与冲正合计分别等于对应流水金额之和。
  - 空结果：区间合法但无流水落入（或订单尚无任何收款/冲正）时返回 200 与空数组 `groups`。
  - 参数无效：缺少 `start`/`end`/`offset` 返回 `start is required` / `end is required` / `offset is required`；`start`/`end` 非法返回以 `start ` / `end ` 开头的可区分错误；`offset` 非法（不是 `Z` 或 `±HH:MM` 写法）返回以 `offset ` 开头的错误；起点晚于终点返回 `start must not be later than end`；均为 400，且参数校验先于数据读取，参数非法时不读取任何订单或流水数据。缺少租户请求头返回 400（`tenant header is required`）。
  - 订单不存在或属于其他租户时返回 404（不泄漏对象是否存在）；查询只汇总本租户名下订单的流水。
- `GET /health`：返回服务与数据库状态。

## 数据与配置

- 数据库文件默认 `var/app.sqlite`（不入库）。
- 环境变量：`APP_DB`（数据库路径）、`APP_PORT`（监听端口）、`APP_TENANT_HEADER`（默认 `X-Tenant`）。

## 当前限制

- 单进程运行，单库写入，未做连接池与写并发调优。
- 租户通过请求头声明，未接入真实身份提供方。
- 无缓存层；批量导入只支持小样本同步方式。
- 收款只支持整单登记，未实现分期、退款（冲正仅冲减已登记收款，不涉及原路退款）；对账能力提供按订单的收款流水清单、按业务发生时间范围的收款/冲正区间查询，以及按对账时区偏移分组的按日收款汇总。
- 流水持久化于同一 SQLite 文件，服务重启后顺序、金额、各次操作后的账务快照与业务发生时间（含登记时的偏移写法与对账归属日期）均保持不变，新操作继续在末尾追加；单库单进程下依赖事务保证追加顺序，未做多副本一致性。
